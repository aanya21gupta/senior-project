# Senior Project - Overview

My final product for my senior project is a GitHub repository containing a complete pipeline for an LLM-based clinical decision support tool. The underlying open-source LLM is BioMistral-7B, a biomedical domain LLM, fine-tuned on real patient data and clinical practice guidelines. It also includes a working web app demo designed for clinician-facing use, where a patient record can be entered and a structured diagnosis prediction and treatment recommendation is returned.

The pipeline operates in two stages. Stage 1 takes structured patient data (trained on a dataset called MIMIC-IV), including vitals, demographics, chief complaint, pre-existing conditions, and medications, and predicts ICD diagnosis codes alongside generating a retrieval query used to search clinical guidelines. Stage 2 uses RAG (retrieval-augmented generation) to match that query against the CREST corpus of annotated clinical practice guidelines via a FAISS vector index and S-PubMedBERT embeddings. It then generates treatment recommendations made of these retrieved guidelines, each cited with its source developer and recommendation strength (strong, moderate, weak, or consensus).

The repository is organized into multiple notebooks that reflect my whole process. One notebook covers data preprocessing and cleaning of the MIMIC-IV dataset, including feature engineering, temporal featurization, encoding of categorical variables, and label formatting. A separate notebook contains the training and evaluation of three classical baseline models: logistic regression, random forest, and Bayesian logistic regression. These notebooks are an integral part of the repository because their results, specifically the consistently poor performance across all three models even after extensive tuning, reflect my initial idea for the project (and my first few weeks of work) and so directly motivate the need for the LLM-based approach. The remaining four notebooks build the LLM pipeline itself: constructing the embeddings with RAG, fine-tuning Stage 1 on MIMIC, fine-tuning Stage 2 on CREST, and wiring everything into a single end-to-end `predict()` function. This two-stage approach is also a major realization and step of my project, as I had to figure out how to connect the two datasets in the model's training and output with one each for diagnosis and treatment. The web app, built with a Next.js frontend and deployed via ngrok and Docker, connects to this final notebook.

The code reflects key research decisions made throughout the project. LoRA (Low-Rank Adaptation) was chosen as the fine-tuning method for its computational efficiency, and the final parameters in the code, including rank, learning rate, and maximum sequence length, represent the best-performing configuration identified through hyperparameter optimization. Interpretability, a core tenet of this project I focused on given its clinical context, is addressed through the RAG citation mechanism itself: every treatment recommendation is attributed to a specific clinical guideline with a labeled recommendation strength, making the model's reasoning transparent without requiring a separate explanation layer.

Model outputs were evaluated by Dr. Maecker with a three-part rough rubric for guidance, assessing each prediction on safety, actionability, and clinical appropriateness. Hyperparameter tuning experiments suggest that the current performance ceiling is data-constrained rather than model-constrained, pointing to a clear direction for future improvement. Ultimately, this tool is designed as a decision support system, not a replacement for physician judgment. The repository represents a fully reproducible proof-of-concept pipeline that could scale meaningfully with richer training data and integration with ambient clinical documentation tools that automatically generate structured patient notes.
